# ЛР12. FOLIA — страница «Статистика» с графиком Plotly.js

Вариант 4 из ЛР12 — «Поиск фильмов (Movie DB)». Страница «Статистика» (`/stats`) показывает горизонтальную столбчатую диаграмму: топ-10 фильмов с самой высокой средней оценкой пользователей. Данные агрегирует бэкенд — эндпоинт `GET /api/analytics/top-movies` из репозитория `lr8`, ветка `lab12`.

## Запуск full-stack приложения

1. Запустить MongoDB.
2. Сервер — репозиторий `lr8`, ветка `lab12`:

   ```bash
   npm install
   cp .env.example .env
   npm run seed     # 18 фильмов и 3354 оценки
   npm start        # http://localhost:4000
   ```

3. Клиент — этот репозиторий:

   ```bash
   npm install
   npm run build && npm run start   # production, http://localhost:3000
   npm run dev                      # или режим разработки
   ```

   Страница статистики — http://localhost:3000/stats, ссылка «Статистика» есть в шапке. Запросы `/api/*` клиент проксирует на API (`API_URL`, по умолчанию `http://localhost:4000`).

## Страница «Статистика»

- `pages/stats.js` — маршрут `/stats`. Данные загружаются в `useEffect` через `fetchTopMovies()` (`lib/api.js`). Страница показывает состояния загрузки, ошибки и пустого результата.
- `components/TopMoviesChart/TopMoviesChart.jsx` — график на Plotly.js. Используются `react-plotly.js/factory` и облегчённая сборка `plotly.js-basic-dist-min`. Компонент подключается через `next/dynamic` с `ssr: false`, потому что Plotly работает только в браузере.
- `lib/topMoviesChart.js` — превращает ответ API в `data`, `layout` и `config` для Plotly.

**Интерактивность.** При наведении на столбец всплывает подсказка: фильм и год, средняя оценка, число оценок, жанры.

**Почему горизонтальные столбцы.** Задача — сравнить одну величину (среднюю оценку) у десяти отдельных фильмов и показать их место в рейтинге. Длина столбца — самый точный для глаза способ сравнить значения. Горизонтальная ориентация вмещает длинные названия фильмов без поворота текста. Порядок сверху вниз совпадает с местом в рейтинге. Круговая диаграмма не подходит, потому что оценки не являются долями целого. Линейный график тоже не подходит: фильмы — не временной ряд.

**Принципы оформления:**
- у графика есть заголовок, у осей — подписи «Средняя оценка (шкала 1–10)» и «Фильм (год выпуска)»;
- шкала начинается с нуля, чтобы длины столбцов честно отражали значения;
- точное значение подписано на каждом столбце;
- один цвет без градиентов, нет легенды (ряд один) и панели инструментов Plotly, сетка светлая;
- на экранах уже 640px названия переносятся на несколько строк, а шаг шкалы увеличивается.

**Доступность.** График обёрнут в `figure` с `role="img"` и текстовым описанием. Под ним раскрывающаяся таблица с теми же данными для скринридеров и клавиатуры.

Plotly не нарушает CSP из ЛР11: стили он вставляет через `<style>`, а это разрешено политикой `style-src 'unsafe-inline'`, скрипты не встраивает.

Тесты:
- `__tests__/topMoviesChart.test.js` — тип и ориентация графика, порядок, шкала от нуля, названия, подсказки, компактный режим;
- `__tests__/stats.test.jsx` — запрос данных, передача в график, таблица, ошибка, пустое состояние, навигация;
- `e2e/stats.spec.js` — в настоящем браузере: 10 столбцов, порядок, подсказка при наведении, отсутствие ошибок и нарушений CSP, axe без нарушений.

## ЛР11. Базовые меры безопасности

Вектор атаки — хранимая XSS через поле «Комментарий к статье».

### Уязвимость

Комментарии поддерживают простое форматирование (`<b>`, `<i>`, `<a href>`), поэтому текст выводится как HTML через `dangerouslySetInnerHTML`. До защиты API сохранял комментарий без изменений, а клиент вставлял его в страницу как есть. Нагрузка `<img src=x onerror="alert('XSS PoC')">` выполнялась у каждого, кто открывал статью. `<script>` при вставке через `innerHTML` браузер не запускает, поэтому для атаки нужен именно обработчик события.

### Защита

| Уровень | Где | Что сделано |
| --- | --- | --- |
| Санитизация на сервере | `lr8`: `utils/sanitize.js`, `middleware/validators.js` | DOMPurify + express-validator: до сохранения в БД и при выдаче остаются только `b`, `strong`, `i`, `em`, `br`, `a[href]` (`http(s):`, `mailto:`); чисто вредоносный комментарий отклоняется с `400` |
| Санитизация при выводе | `lib/sanitize.js` | DOMPurify с тем же списком тегов перед `dangerouslySetInnerHTML` — на случай, если в ответе API окажется непроверенный HTML |
| Заголовки Helmet | `server.js` | Next.js запускается через Express, Helmet выставляет заголовки на каждый ответ, включая HTML-страницы |
| CSP | `server.js` | `script-src 'self'`, `script-src-attr 'none'`, `object-src 'none'`, `frame-ancestors 'none'`, `base-uri 'self'`, `form-action 'self'`; стили и шрифты — с `self` и Google Fonts |

CSP передаётся заголовком вместе с HTML-документом, поэтому Helmet подключён именно к серверу, который отдаёт страницы, а не только к API.

Сборка переведена на webpack (`next build --webpack`): Turbopack встраивает в страницу inline-скрипт загрузки чанков, который строгая политика `script-src 'self'` блокирует. При webpack-сборке на страницах только внешние скрипты и `__NEXT_DATA__` типа `application/json`, который CSP не затрагивает.

В режиме разработки к `script-src` добавляется `'unsafe-eval'` — без него не работает горячая перезагрузка webpack.

Проверка заголовков:

```bash
curl -I http://localhost:3000/posts/olive-ink
```

Тесты безопасности — `e2e/security.spec.js`, `__tests__/sanitize.test.js` и `__tests__/CommentInput.test.jsx`. Они проверяют:
- наличие заголовков Helmet и CSP у страницы;
- что вредоносный HTML из API не выполняется, а форматирование сохраняется;
- что CSP блокирует встроенный обработчик, даже если очистку обойти.

## ЛР10. Веб-доступность

### Аудит доступности

Автоматический аудит — axe-core (`@axe-core/playwright`) и Lighthouse (категория Accessibility). Скрипт `scripts/a11y-audit.mjs` проверяет четыре состояния: главная, главная с открытыми комментариями, страница статьи и страница статьи с ошибкой пустого комментария. Правила — WCAG 2.1 A/AA и best practices.

```bash
npm run build && npm run start
npm run audit:a11y          # отчёт в a11y-report/axe.html и axe.json
npx lighthouse http://localhost:3000 --only-categories=accessibility --view
```

| Проверка | До | После |
| --- | --- | --- |
| axe, нарушений (4 состояния) | 16 | 0 |
| Lighthouse, главная | 96 | 100 |
| Lighthouse, статья | 94 | 100 |

Тесты в `e2e/a11y.spec.js` (запускаются вместе с остальными через `npm run test:e2e`) прогоняют axe на ключевых страницах и проходят сценарий комментирования только с клавиатуры.

### Исправленные проблемы

| Проблема | Как проявлялась | Как исправлена |
| --- | --- | --- |
| Кнопка «Нравится» без корректного текстового имени | `aria-label="Нравится"` перекрывал видимый счётчик: скринридер не озвучивал число лайков, axe — `label-content-name-mismatch` (WCAG 2.5.3) | Вместо `aria-label` — скрытый текст `.visually-hidden`, имя кнопки «Нравится: 0»; иконки `aria-hidden`, у иконки «Поделиться» есть `aria-label` и `title` |
| Поле комментария без `<label>` | Подпись была только в placeholder, который пропадает при вводе; ошибка пустого комментария не связана с полем и не озвучивалась | Видимый `<label htmlFor>` со связкой через `useId`; при ошибке `aria-invalid`, `aria-describedby` и `role="alert"`, фокус возвращается в поле; об успешной публикации сообщает `role="status"` |
| Обложки статей с пустым `alt` | `alt=""` — изображение считалось декоративным и пропадало из дерева доступности | Поле `imageAlt` в `data/articles.js` с описанием обложки, используется в карточке и на странице статьи |
| Порядок фокуса и видимость фокуса | Не было ссылки пропуска навигации; у поля ввода `outline: none`; кнопка комментариев не указывала, что раскрывает | Ссылка «Перейти к содержимому» первой в порядке Tab, `:focus-visible` с обводкой 3px для ссылок и кнопок, `:focus-within` для поля; `aria-expanded` и `aria-controls` у кнопки «Комментарий» |
| Контраст и семантика | Серый текст `#7a7568` — 4.45:1 на фоне и 3.73:1 в комментариях (нужно 4.5:1); граница поля 1.75:1 (нужно 3:1); на главной нет `h1`, на странице статьи нет `main` | `--muted: #686457` (5.74:1 и 4.81:1), граница поля `#8f8774` (3.46:1); `main` на обеих страницах, скрытый `h1` на главной, карточки — список `ul/li`, `article` подписан заголовком, комментарии — секция с `h2` |

## Запуск приложения

```bash
npm install
npm run dev                       # разработка
npm run build && npm run start    # production
```

Оба режима запускают `server.js` — Express с Helmet, который передаёт запросы в Next.js. Порт задаётся переменной `PORT`. Приложение открывается на http://localhost:3000. Запросы `/api/*` Next.js проксирует на API (`rewrites` в `next.config.mjs`), по умолчанию на http://localhost:4000. Другой адрес задаётся переменной `API_URL` при сборке или запуске.

## Unit-тесты (Jest)

```bash
npm test
```

Jest настроен через `next/jest` (`jest.config.js`), компоненты тестируются с React Testing Library. Тесты лежат в `__tests__/`:

- `formatTimeAgo.test.js` — функция `lib/formatTimeAgo.js` форматирует дату публикации комментария («только что», «5 минут назад», «2 часа назад», «3 дня назад»), некорректная дата даёт пустую строку.
- `LikeButton.test.jsx` — при клике счётчик лайков увеличивается на 1.
- `CommentInput.test.jsx` — модуль `lib/api.js` замокан через `jest.mock()`. Проверяются:
  - загрузка комментариев и отправка нового;
  - запрет пустой отправки;
  - вывод форматирования без выполнения вредоносного HTML;
  - показ причины, по которой сервер отклонил комментарий.
- `sanitize.test.js` — `lib/sanitize.js` удаляет `<script>`, обработчики `on*` и `javascript:`-ссылки, оставляя разрешённое форматирование.

## E2E-тест (Playwright)

Перед первым запуском установите браузер:

```bash
npx playwright install chromium
```

Запуск:

```bash
npm run test:e2e
```

Интерфейс Test Runner:

```bash
npx playwright test --ui
```

Playwright сам собирает и запускает приложение на порту 3100 (`webServer` в `playwright.config.js`). API и MongoDB для теста не нужны: запросы к `/api/comments` и `/api/analytics/top-movies` перехватываются и мокаются через `page.route()`.

Сценарий «Комментирование статьи» (`e2e/comment.spec.js`):

1. Пользователь открывает главную страницу и переходит на статью «Оливковые чернила».
2. Тест проверяет адрес `/posts/olive-ink`, заголовок статьи и пустой список комментариев.
3. Пользователь вводит текст в поле комментария и нажимает «Отправить».
4. Тест проверяет, что комментарий появился в списке под статьёй, поле очистилось, а в перехваченном `POST` ушли правильные данные.

## Структура

- `pages/` — маршруты, `_app.js` и `_document.js`.
- `components/` — `ArticleCard`, `LikeButton`, `CommentInput`, `SiteHeader`, `TopMoviesChart`.
- `server.js` — Express-сервер с Helmet и CSP поверх Next.js.
- `lib/api.js` — запросы к API комментариев и статистики.
- `lib/topMoviesChart.js` — настройки графика Plotly.
- `lib/sanitize.js` — очистка HTML комментариев через DOMPurify.

- `data/articles.js` — mock-данные статей.
- `__tests__/` — unit-тесты; `e2e/` — E2E-тесты, включая проверки доступности и безопасности.
