# ЛР10. FOLIA — веб-доступность (WCAG)

Вариант 4, блоговая платформа. Основа — приложение из лабораторной работы №9 (Next.js, Jest, Playwright). Аудит проводился для карточек статей, формы комментирования и кнопки «Нравится».

## Аудит доступности

Автоматический аудит — axe-core (`@axe-core/playwright`) и Lighthouse (категория Accessibility). Скрипт `scripts/a11y-audit.mjs` проверяет четыре состояния: главная, главная с открытыми комментариями, страница статьи и страница статьи с ошибкой пустого комментария. Правила — WCAG 2.1 A/AA и best practices.

```bash
npm run build && npm run start
npm run audit:a11y          # отчёт в a11y-report/axe.html и axe.json
npx lighthouse http://localhost:3000 --only-categories=accessibility --view
```

| Проверка | До | После |
| --- | --- | --- |
| axe, нарушений (4 состояния) | 16 | 0 |
| Lighthouse, главная | 96 | 100 |
| Lighthouse, статья | 94 | 100 |

Тесты в `e2e/a11y.spec.js` (запускаются вместе с остальными через `npm run test:e2e`) прогоняют axe на ключевых страницах и проходят сценарий комментирования только с клавиатуры.

## Исправленные проблемы

| Проблема | Как проявлялась | Как исправлена |
| --- | --- | --- |
| Кнопка «Нравится» без корректного текстового имени | `aria-label="Нравится"` перекрывал видимый счётчик: скринридер не озвучивал число лайков, axe — `label-content-name-mismatch` (WCAG 2.5.3) | Вместо `aria-label` — скрытый текст `.visually-hidden`, имя кнопки «Нравится: 0»; иконки `aria-hidden`, у иконки «Поделиться» есть `aria-label` и `title` |
| Поле комментария без `<label>` | Подпись была только в placeholder, который пропадает при вводе; ошибка пустого комментария не связана с полем и не озвучивалась | Видимый `<label htmlFor>` со связкой через `useId`; при ошибке `aria-invalid`, `aria-describedby` и `role="alert"`, фокус возвращается в поле; об успешной публикации сообщает `role="status"` |
| Обложки статей с пустым `alt` | `alt=""` — изображение считалось декоративным и пропадало из дерева доступности | Поле `imageAlt` в `data/articles.js` с описанием обложки, используется в карточке и на странице статьи |
| Порядок фокуса и видимость фокуса | Не было ссылки пропуска навигации; у поля ввода `outline: none`; кнопка комментариев не указывала, что раскрывает | Ссылка «Перейти к содержимому» первой в порядке Tab, `:focus-visible` с обводкой 3px для ссылок и кнопок, `:focus-within` для поля; `aria-expanded` и `aria-controls` у кнопки «Комментарий» |
| Контраст и семантика | Серый текст `#7a7568` — 4.45:1 на фоне и 3.73:1 в комментариях (нужно 4.5:1); граница поля 1.75:1 (нужно 3:1); на главной нет `h1`, на странице статьи нет `main` | `--muted: #686457` (5.74:1 и 4.81:1), граница поля `#8f8774` (3.46:1); `main` на обеих страницах, скрытый `h1` на главной, карточки — список `ul/li`, `article` подписан заголовком, комментарии — секция с `h2` |

## Запуск приложения

```bash
npm install
npm run dev
```

Приложение открывается на http://localhost:3000. Запросы `/api/*` Next.js проксирует на API (`rewrites` в `next.config.mjs`), по умолчанию на http://localhost:4000. Другой адрес задаётся переменной `API_URL` при сборке или запуске.

## Unit-тесты (Jest)

```bash
npm test
```

Jest настроен через `next/jest` (`jest.config.js`), компоненты тестируются с React Testing Library. Тесты лежат в `__tests__/`:

- `formatTimeAgo.test.js` — функция `lib/formatTimeAgo.js` форматирует дату публикации комментария («только что», «5 минут назад», «2 часа назад», «3 дня назад»), некорректная дата даёт пустую строку.
- `LikeButton.test.jsx` — при клике счётчик лайков увеличивается на 1.
- `CommentInput.test.jsx` — модуль `lib/api.js` замокан через `jest.mock()`. Проверяются загрузка комментариев, отправка нового комментария и запрет пустой отправки.

## E2E-тест (Playwright)

Перед первым запуском установите браузер:

```bash
npx playwright install chromium
```

Запуск:

```bash
npm run test:e2e
```

Интерфейс Test Runner:

```bash
npx playwright test --ui
```

Playwright сам собирает и запускает приложение на порту 3100 (`webServer` в `playwright.config.js`). API и MongoDB для теста не нужны: запросы к `/api/comments` перехватываются и мокаются через `page.route()`.

Сценарий «Комментирование статьи» (`e2e/comment.spec.js`):

1. Пользователь открывает главную страницу и переходит на статью «Оливковые чернила».
2. Тест проверяет адрес `/posts/olive-ink`, заголовок статьи и пустой список комментариев.
3. Пользователь вводит текст в поле комментария и нажимает «Отправить».
4. Тест проверяет, что комментарий появился в списке под статьёй, поле очистилось, а в перехваченном `POST` ушли правильные данные.

## Структура

- `pages/` — маршруты, `_app.js` и `_document.js`.
- `components/` — `ArticleCard`, `LikeButton`, `CommentInput`, `SiteHeader`.
- `lib/api.js` — запросы к API комментариев.
- `lib/formatTimeAgo.js` — форматирование даты публикации.
- `data/articles.js` — mock-данные статей.
- `__tests__/` — unit-тесты, `e2e/` — E2E-тесты, включая проверки доступности.
- `scripts/a11y-audit.mjs` — автоматический аудит axe-core.
